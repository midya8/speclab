SPECULATIVE DECODING / STOPPING RULES

Stopping is
not censoring.

You can stop drafting after a token. You cannot quietly erase that sample and pretend the remaining proposal still came from the same distribution.

Exact rational arithmetic. Complete finite laws.

This lab keeps every stopped proposal leaf, acceptance branch, correction and output sequence. It contrasts two safe stopping rules with an intentionally wrong sample-censoring control.

01 / Set up a finite world

1-3 tokens · horizon 1-4 · maximum 3 draft tokens

Edit every target and draft conditional

p is target, q is draft. Use integers or exact strings such as 1/3 or 0.25. Each row must sum to one. Tables include unreachable prefixes. Changes invalidate the old evidence until recomputed.

Acceptance is min(1,p(x)/q(x)). First rejection draws from normalized (p-q)+. If all retained proposals pass, draw a bonus from p. Zero-mass proposals and branches are never enumerated. Empty retained paths still draw from p, which is exactly where the censoring control gets into trouble.

05 / Reproduce, then distrust

Download the edited input and full exact report. A separate Python implementation enumerates all maximum-length draft paths, marginalizes unused suffixes and expands decoding states forward. It never imports the stopped-tree producer.

python -m speclab.stopping_cli audit input.json > report.json
python -m speclab.stopping_cli verify input.json report.json

Limits: hand-specified finite models, no trained predictor, no entropy approximation, no EOS or tokenizer mismatch, no target-dependent stopping, no production library audit. This is not a new speculative decoding algorithm. The wrong censoring rule is deliberately constructed here, not attributed to any library.
